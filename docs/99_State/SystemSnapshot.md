# 📊 Отчет о состоянии системы (Snapshot) — 16.03.2026

## 🏗 Архитектура проекта
Система представляет собой SaaS-платформу для автоматизации учебных заказов, состоящую из четырех ключевых компонентов, развернутых в Docker-окружении.

1.  **Frontend (MiniApp)**: React + Vite. Работает внутри Telegram WebApp.
2.  **Backend (API)**: FastAPI. Обеспечивает бизнес-логику и безопасность.
3.  **Bot (Telegram)**: Aiogram 3. Основной интерфейс взаимодействия для админов и исполнителей.
4.  **Database**: PostgreSQL (SQLAlchemy + Alembic).

---

## ✅ Текущий прогресс (Статус: Active Development)

### 1. UX/UI и интерфейс бота
- **Технология "Одного окна"**: Реализован бесшовный UX. Бот редактирует текущее сообщение вместо отправки новых, что исключает замусоривание чата.
- **Role-Switching**: Система динамически меняет интерфейс в зависимости от выбранного режима:
    - **Админ**: Управление заказами, статистика (заглушка), пользователи (заглушка).
    - **Исполнитель**: Кабинет заказов, баланс (заглушка).
    - **Клиент**: Личный кабинет, FAQ, подача заявок.
- **Навигация**: Исправлена логика кнопок "Назад" (восстановление изображений и контекста режима).

### 2. Жизненный цикл заказа (Order Flow)
- **Создание**: Клиент создает заказ через MiniApp (защищено валидацией `initData`).
- **Назначение**: Админ выбирает исполнителя из списка активных/верифицированных.
- **Уведомления**: Полностью налажена система оповещений (админ -> исполнителю, исполнитель -> админу/клиенту).
- **Сдача работы**: Исполнитель может загрузить документ, который улетает админу на проверку.
- **Завершение**: Админ может утвердить работу (статус `done`) или отправить на доработку.

### 3. Инфраструктура и безопасность
- **Docker**: Конфигурация отлажена, переменные окружения (`ADMIN_IDS`) корректно пробрасываются в контейнеры.
- **Безопасность API**: Внедрена проверка HMAC-подписи для всех запросов из MiniApp. Прямой доступ к БД снаружи закрыт.
- **Data Seeding**: Подготовлены скрипты для быстрой генерации тестовых данных и настройки ролей.
