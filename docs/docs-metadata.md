# Docs Metadata — Стандарт документации проекта

## Назначение

Каждый `.md` файл в папке `docs/` проекта ОБЯЗАН содержать YAML frontmatter
с метаданными. Это обеспечивает:

- Быстрое ознакомление AI-агента с проектом через `docs/INDEX.md`
- Автоматическое определение какие документы затронуты при изменениях в коде
- Синхронизацию с Notion (поля маппятся 1:1 на свойства страниц)
- Отслеживание актуальности документации

---

## Структура документации

```
docs/
├── INDEX.md                  # Точка входа — карта всей документации
│
├── 01_System/                # Архитектура и общее устройство
│   ├── Overview.md           # Компоненты, схема, стек
│   └── DataModel.md          # Таблицы, связи, Enum
│
├── 02_Backend/               # Серверная часть
│   ├── API.md                # Эндпоинты, форматы
│   ├── Bot.md                # Хендлеры, FSM, клавиатуры
│   └── Services.md           # Бизнес-логика
│
├── 03_Frontend/              # Клиентская часть
│   ├── Structure.md          # Компоненты, роутинг, страницы
│   └── Config.md             # Подключение к API, proxy, env
│
├── 04_DevOps/                # Запуск и деплой
│   ├── LocalSetup.md         # Пошаговый запуск локально
│   ├── Deploy.md             # Продакшен, Docker, CI
│   └── Secrets.md            # Работа с .env
│
└── 99_State/                 # Живое состояние проекта
    ├── Changelog.md          # Лог изменений (новое сверху)
    └── Issues.md             # Баги, техдолг, TODO
```

### Правила структуры

- Папки нумеруются с префиксом `NN_` для логического порядка чтения
- `99_State/` — «горячая» зона, обновляется при каждом значимом изменении
- Файлы именуются на английском в PascalCase: `DataModel.md`, `LocalSetup.md`
- Для масштабирования: создавай новую папку `05_НовыйРаздел/` и добавляй запись в `INDEX.md`

## Формат YAML Frontmatter

Каждый `.md` файл в `docs/` ОБЯЗАН начинаться с блока:

```yaml
---
title: "Название документа"
scope: backend/api
updated: 2026-03-13
status: actual

category: "Разработка"
type: "Документация"
tags: [Backend, API, Auth]
description: "Краткое описание содержимого — 1-2 предложения"
---
```

---

## Описание полей

### Обязательные технические поля

| Поле | Тип | Описание |
|------|-----|----------|
| `title` | string | Название документа, человекочитаемое |
| `scope` | string | Путь(и) в проекте к которым относится документ. Несколько — через запятую |
| `updated` | date | Дата последнего обновления в формате `YYYY-MM-DD` |
| `status` | enum | Состояние актуальности документа |

### Обязательные Notion-совместимые поля

| Поле | Тип | Описание |
|------|-----|----------|
| `category` | enum | Категория документа (маппится на секцию в Notion) |
| `type` | enum | Тип контента |
| `tags` | list | Теги для фильтрации и поиска |
| `description` | string | 1-2 предложения о содержимом документа |

---

## Допустимые значения

### `status`

| Значение | Когда использовать |
|----------|-------------------|
| `actual` | Документ соответствует текущему состоянию кода |
| `outdated` | Известно что документ устарел, требуется ревизия |
| `draft` | Документ в работе, НЕ является источником правды |

### `category`

| Значение | Для каких папок | Описание |
|----------|----------------|----------|
| `Архитектура и система` | `01_System/` | Общее устройство, модель данных |
| `Разработка` | `02_Backend/`, `03_Frontend/` | Код, API, компоненты |
| `DevOps и инфраструктура` | `04_DevOps/` | Запуск, деплой, конфигурация |
| `Состояние и планирование` | `99_State/` | Changelog, баги, задачи |

### `type`

| Значение | Описание |
|----------|----------|
| `Документация` | Описывает текущее состояние (как есть) |
| `Задача` | Описывает что нужно сделать (Issues, Backlog) |

### `tags` — допустимые значения

**По зоне:**
`Frontend`, `Backend`, `API`, `DevOps`, `Database`

**По типу работы:**
`Security`, `Auth`, `UX`, `Bug`, `Feature`, `Config`

Теги комбинируются свободно. При необходимости новый тег можно добавить,
но сначала убедись что существующие не покрывают нужное.

## Правила для AI-агентов

### При создании нового документа

1. Определи в какую папку `docs/` он относится
2. Заполни ВСЕ поля frontmatter (пропуск обязательных полей запрещён)
3. Установи `status: draft` пока документ не проверен
4. Добавь запись в `docs/INDEX.md`

### При редактировании документа

1. Обнови поле `updated` на текущую дату
2. Если содержимое изменилось существенно — проверь актуальность `tags` и `description`
3. Если документ был `outdated` и ты его актуализировал — смени на `status: actual`

### При изменении кода проекта

1. Определи какие файлы в `docs/` имеют `scope`, совпадающий с изменённой частью кода
2. Проверь затронутые документы на актуальность
3. Если документ больше не соответствует коду — установи `status: outdated`
4. В идеале — сразу актуализируй документ и обнови `updated`

### Принцип «один факт — одно место»

- Каждый факт (схема таблицы, эндпоинт, команда запуска) описывается ТОЛЬКО в одном документе
- Если факт нужен в другом месте — ставь ссылку: `→ см. 01_System/DataModel.md#orders`
- НИКОГДА не копируй блоки текста между документами

## INDEX.md — формат точки входа

Файл `docs/INDEX.md` содержит:

1. **Шапку проекта** — название, стек, дата обновления
2. **Карту документов** — таблица: путь к файлу, description, status
3. **Правила обновления** — краткая инструкция для AI (ссылка на этот скилл)

AI-агент при первом знакомстве с проектом ВСЕГДА начинает с `docs/INDEX.md`.
