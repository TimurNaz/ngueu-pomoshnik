# Аудит архитектуры фронтенда

## Критические проблемы

### 1. Захардкоженный fallback user ID
**Файл:** `useTelegram.js:9`

Если Telegram SDK недоступен, используется `id: 123456789`. Можно создать заказ от чужого имени при тестировании в браузере.

**Решение:** убрать fallback, показывать ошибку авторизации.

### 2. Urgency enum mismatch
**Файл:** `NewOrder.jsx:140`

Фронтенд шлёт `3d`, `1w`, `2w`, `1m`. Бэкенд ждёт `three_days`, `one_week`, `two_weeks`, `one_month`. Хрупкий маппинг на стороне API.

**Решение:** маппинг на фронте перед отправкой или единый формат.

### 3. Нет Error Boundary
Если любой компонент крашится — белый экран без обратной связи.

**Решение:** добавить React Error Boundary.

### 4. localStorage без try-catch
**Файлы:** `App.jsx:12`, `Onboarding.jsx:25`

В приватном режиме браузера `localStorage` может выбросить ошибку, приложение упадёт.

**Решение:** обернуть в `try-catch`.

## Архитектурные проблемы

### 5. Нет глобального стейта
Каждая страница сама фетчит данные пользователя — `Home.jsx`, `Orders.jsx`, `Profile.jsx` все делают `GET /api/users/{id}` независимо. Нет кеширования, нет общего контекста.

**Решение:** React Context для данных пользователя или React Query.

### 6. Дублирование кода
Маппинг иконок статусов скопирован в 3 места: `Home.jsx:58`, `Orders.jsx:61`, `OrderDetail.jsx:60`.

**Решение:** вынести в `constants.js`.

### 7. Захардкоженные значения

| Файл | Значение | Проблема |
|------|----------|----------|
| `Profile.jsx:119` | `5.0` | Рейтинг захардкожен |
| `Profile.jsx:214` | `'НГУЭУ/Помощник v1.0'` | Версия в строке |
| `NewOrder.jsx:82` | `30 * 1024 * 1024` | Лимит файла magic number |
| `OrderDetail.jsx:176` | `'#ff4d4f'` | Цвет вне дизайн-системы |
| `FAQ.jsx:3-87` | Весь FAQ | Контент прямо в компоненте |

**Решение:** создать `constants.js`, вынести все значения.

### 8. API-ответы не валидируются
Все `fetch()` вызовы предполагают конкретную структуру ответа без проверки. Если бэкенд вернёт другой формат — молча сломается.

### 9. Нет обработки ошибок сети
Везде одинаковый паттерн: `catch(err) { console.error(err) }`. Пользователь не видит что пошло не так — нет различия между 404, 500, таймаутом.

## Стилизация и UX

### 10. Inline-стили обходят дизайн-систему
`OrderDetail.jsx:142-147` использует `style={{}}` вместо CSS-классов из `variables.css`.

### 11. Эмодзи вместо иконок
Статусы, категории — везде эмодзи. Проблема для скринридеров и визуальной консистентности.

### 12. `window.confirm()` вместо модалки
`OrderDetail.jsx:35` — нативный `confirm()` выглядит чужеродно в Mini App.
