# Руководство по локальному запуску и разработке

Данное руководство описывает процесс запуска проекта в Docker-контейнерах с использованием собственного домена (`olddiamond.online`) через Cloudflare Tunnel.

---

## 🚀 Ежедневный рабочий процесс

Для полноценной работы проекта (Frontend + Backend + Bot) необходимо выполнить два шага в разных окнах терминала.

### Шаг 1: Запуск инфраструктуры (Docker)
Запускает базу данных, API, Telegram-бота и Frontend (вместе с Nginx-прокси).

```bash
# Перейдите в корень проекта
cd ~/ngueu-pomoshnik

# Запустите все сервисы в фоновом режиме
docker compose up -d
```

### Шаг 2: Запуск туннеля (Cloudflare)
Связывает ваш локальный компьютер с доменом `olddiamond.online`, обеспечивая HTTPS и доступ для Telegram Mini App.

```bash
# Проброс локального порта 3000 на ваш домен
cloudflared tunnel run --url http://localhost:3000 ngueu-tunnel
```
*Это окно терминала должно оставаться открытым во время работы.*

## 🛠 Управление проектом

### Мониторинг и логи
Чтобы понять, что происходит внутри контейнеров (например, увидеть ошибки бота или API):

*   **Все логи сразу:** `docker compose logs -f`
*   **Только Telegram бот:** `docker compose logs -f bot`
*   **Только Бэкенд (API):** `docker compose logs -f api`
*   **Статус контейнеров:** `docker compose ps`

### Остановка проекта
*   **Приостановить:** `docker compose stop` (данные и контейнеры сохраняются)
*   **Полная очистка:** `docker compose down` (удаляет контейнеры и временные сети)

### Применение изменений (Пересборка)
Если вы изменили код или зависимости (`requirements.txt`, `package.json`):

*   **Обновить фронтенд:** `docker compose up -d --build frontend`
*   **Обновить бота:** `docker compose up -d --build bot`
*   **Обновить всё разом:** `docker compose up -d --build`

## 🗄 Работа с базой данных (PostgreSQL)

База данных внутри Docker проброшена на ваш локальный компьютер на нестандартный порт, чтобы избежать конфликтов с системным Postgres.

**Реквизиты для подключения (DBeaver, TablePlus, etc.):**
*   **Host:** `localhost` (или `127.0.0.1`)
*   **Port:** `5435`
*   **User:** `postgres`
*   **Password:** `postgres` (проверьте в `.env`)
*   **Database:** `ngueu_db`

**Миграции (Alembic):**
Если вы изменили модели данных или запускаете проект на новой базе:
```bash
docker compose exec api alembic upgrade head
```

## 🌐 Архитектура сети (Как это работает)

1.  **Cloudflare Tunnel:** Принимает трафик на `https://olddiamond.online` и направляет его на ваш порт `3000`.
2.  **Nginx (Frontend контейнер):** Слушает порт `3000` и распределяет запросы:
    *   `/api/*` — проксирует в контейнер `api:8000`
    *   `/static/*` — проксирует в контейнер `api:8000`
    *   Все остальное — отдает React-приложение.
3.  **Frontend Config:** Использует `window.location.origin`, поэтому автоматически работает на любом домене.

---

## ⚠️ Важные примечания
*   **Telegram Bot:** В BotFather должен быть указан адрес `https://olddiamond.online`.
*   **.env файлы:** Для корректной работы `docker-compose` рекомендуется держать файл `.env` в корне проекта (рядом с `docker-compose.yml`).
*   **HTTPS:** Cloudflare автоматически предоставляет SSL-сертификат, что необходимо для работы Telegram WebApp.

## 🔧 Решение проблем (Troubleshooting)

### 1. Если не приходят уведомления в Telegram
Это происходит, когда API не видит `BOT_TOKEN`.
*   **Решение:** Убедитесь, что файл `.env` скопирован в корень проекта.
*   **Команда:** `cp backend/bot/.env .env` -> `docker compose down` -> `docker compose up -d`.

### 2. Если в админке пуст список исполнителей
В базе отсутствуют пользователи с ролью `executor` и флагом `is_verified=True`.
*   **Решение:** Запустите скрипт генерации тестовых данных:
    `docker compose exec api python backend/utils/scripts/generate_test_data.py`

### 3. Ошибка 413 (Entity Too Large) при загрузке файлов в Mini App
Если в обычном браузере всё работает, а в Telegram — нет:
1.  **Nginx:** Проверьте, что в `nginx.conf` стоит `client_max_body_size 100M`.
2.  **Cloudflare:** Отключите **Bot Fight Mode** и установите **Security Level** на **Low**.
3.  **Кэш Telegram:** Очистите кэш приложения (`Настройки -> Данные и память -> Использование памяти -> Очистить кэш Telegram`).

## 🧬 Миграции базы данных (Alembic)

Миграции — это «система контроля версий» для вашей базы данных. Они нужны, чтобы при изменении моделей в коде Python (`models.py`) база данных знала, как именно изменить свою структуру, не теряя данные.

### Зачем это нужно?
*   **История изменений:** Можно увидеть, как менялась структура базы со временем.
*   **Синхронизация:** Позволяет легко развернуть проект на новом сервере с точно такой же структурой таблиц.
*   **Сохранность:** Позволяет добавлять новые колонки или таблицы в уже работающую базу с данными.

### Основные команды
Если вы изменили файл `models.py` (добавили поле или новую таблицу):

1.  **Создать файл миграции** (автоматически определит изменения):
    ```bash
    docker compose exec api alembic revision --autogenerate -m "Описание изменений"
    ```
2.  **Применить изменения к базе:**
    ```bash
    docker compose exec api alembic upgrade head
    ```
3.  **Посмотреть текущий статус:**
    ```bash
    docker compose exec api alembic current
    ```

*Все файлы миграций хранятся в папке `backend/migrations/versions`.*

## 💾 Резервное копирование (Backups)

Папка `backups` служит для хранения полных снимков (SQL-дампов) базы данных. 

### Как сделать бэкап вручную?
Рекомендуется делать бэкап перед выполнением сложных миграций или при обновлении сервера.
```bash
python3 backend/utils/scripts/backup_db.py
```
*Скрипт создаст .sql файл с текущей датой и временем.*

### Как восстановить базу из бэкапа?
Если нужно вернуть базу к состоянию из файла:
```bash
docker compose exec -T db psql -U postgres -d ngueu_db < backups/название_файла.sql
```
