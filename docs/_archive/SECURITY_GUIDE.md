# 🛡 Руководство по безопасности проекта (Security Guide)

Этот документ содержит правила работы с секретными данными, ключами и токенами. Соблюдение этих правил гарантирует сохранность твоего кода, базы данных и денег на счету в облаке.

---

## 🔑 1. SSH Ключи (Твой цифровой паспорт)

Для доступа к серверу Яндекс Облака используется пара ключей:
*   **Приватный (`id_rsa`)**: Лежит в `~/.ssh/` на твоем Маке. **НИКОГДА** не копируй его в файлы проекта, не пересылай в мессенджерах и не выкладывай в Git. Это ключ, который открывает дверь в твой сервер.
*   **Публичный (`id_rsa.pub`)**: Его можно давать кому угодно. Мы вставили его в панель Яндекса, чтобы сервер "узнавал" твой компьютер.

**Что делать, если приватный ключ утерян/украден?**
1. Удали старый публичный ключ из панели Яндекс Облака.
2. Сгенерируй новую пару ключей (`ssh-keygen`).
3. Добавь новый публичный ключ на сервер.

## 🎟 2. Токены GitLab (Personal Access Tokens)

Токен (`glpat-...`) — это замена твоего пароля для Git. Он дает право читать и менять код. Это **«мастер-ключ»** от твоего цифрового дома.

### Что может произойти при утечке токена:
1.  **Кража исходного кода**: Любой, кто узнает токен, сможет полностью скачать весь проект со всеми наработками.
2.  **Захват сервера (Критично)**: Злоумышленник может зайти в настройки CI/CD GitLab, достать оттуда твой приватный SSH-ключ и получить полный доступ к серверу в Яндекс Облаке. Итог: удаление БД, кража данных или использование сервера для майнинга за твой счет.
3.  **Порча проекта**: Хакер сможет залить вредоносный код или удалить все файлы одной командой `git push --force`.
4.  **Доступ к секретам**: Через API GitLab можно прочитать переменные окружения, включая `BOT_TOKEN`, получив полный контроль над ботом.

**Действие при утечке**: Если токен попал в логи чата или был случайно засвечен — он считается скомпрометированным. Зайди в GitLab -> Preferences -> Access Tokens и нажми **Revoke**. Создай новый. **Отзыв токена мгновенно превращает его в бесполезный набор символов.**

## 📄 3. Файлы конфигурации (.env)

Файл `.env` содержит самые "вкусные" данные для хакера: токен Telegram-бота и пароль от базы данных.

*   **Никакого Git**: Файл `.env` должен быть прописан в `.gitignore`. Он живет только локально у тебя и на реальном сервере.
*   **Разделение**: Пароль от базы данных на сервере (`production`) должен отличаться от того, что ты используешь при разработке (`local`).

---

## 🌐 4. Сетевая безопасность

*   **Docker**: Мы используем внутреннюю сеть Docker. База данных (`db`) не видна из интернета, она доступна только внутри сервера для бота и API. Это защищает данные от перебора паролей.
*   **Cloudflare Tunnel**: Мы используем туннель вместо открытия портов. Это значит, что твой сервер "спрятан" за броней Cloudflare. Никто не сможет просканировать сервер на уязвимости открытых портов.

---

## 🚨 5. План действий при инциденте (Incident Response)

Если ты понял, что данные утекли:
1.  **Бот**: Смени `BOT_TOKEN` через `@BotFather` (команда `/revoke`). Это мгновенно отключит старый токен.
2.  **Git**: Отзови все токены в GitLab.
3.  **Сервер**: Смени пароль пользователя `postgres` в базе данных и обнови его в `.env`.
4.  **SSH**: Если украден `id_rsa`, удали его из `authorized_keys` на сервере.
