# Оценка проекта НГУЭУ/Помощник (28.02.2026)

## Общая картина

Проект находится на **стадии рабочего MVP**. Ядро системы построено грамотно, бизнес-модель проработана глубоко, но есть несколько блокирующих и критических проблем, которые нужно устранить до серьёзного использования.

---

## Что сделано хорошо

**Архитектура и дата-модель**
- 9 таблиц покрывают полный жизненный цикл заказа: от создания до оплаты и отзыва
- Продуманная бонусная система (`LOYALTY_THRESHOLDS`, `CASHBACK_RATES`, реферальная программа)
- Сервисный слой (`db_service.py`) чётко разделён по ответственностям

**Frontend**
- Дизайн-система задокументирована в `CLAUDE.md` — BEM, CSS-токены, компоненты описаны
- UX формы заявки (3 шага) — правильный подход, есть валидация и haptic feedback
- Онбординг показывается только один раз через `localStorage`

**DevOps-база**
- Docker Compose с 4 сервисами работает на продакшне
- Скрипт `deploy.sh` автоматизирует деплой
- Alembic миграции настроены

## Критические проблемы (нужно исправить сейчас)

### 1. Порт БД открыт наружу
**Файл:** `docker-compose.yml:14`

В `IMPROVEMENTS.md` зафиксировано — сотни брутфорс-атак в логах. Одна строка исправит это.

```yaml
# УДАЛИТЬ:
ports:
  - "5432:5432"
```

### 2. Нет аутентификации в API
`POST /api/orders` принимает `client_id` как параметр тела запроса. Любой знающий чужой `user_id` может создать заказ от его имени. Минимум — валидировать Telegram `initData` в заголовке запроса.

### 3. Urgency мисматч между фронтендом и БД
**Файл:** `frontend/src/pages/NewOrder.jsx:15-20`

```js
// Фронт шлёт:
{ id: '3d' },  { id: '1w' },  { id: '2w' },  { id: '1m' }

// БД ждёт (models.py):
three_days,    one_week,      two_weeks,     one_month
```

Значение `1m` отсутствует в Enum — **гарантированная ошибка** при выборе "Больше месяца".

### 4. Хардкод userId в продакшн-коде
**Файл:** `frontend/src/pages/NewOrder.jsx:125`

```js
const userId = user?.id || 927125510; // чужой реальный ID как fallback
```
