# 🚀 План улучшений и анализ логов (28.02.2026)

Этот документ содержит выводы на основе анализа логов работающего сервера и рекомендации по улучшению безопасности и наблюдаемости (observability) проекта.

---

## 🛠 Выявленные проблемы (Critical)

### 1. Конфликт инстансов Бота
**Проблема:** В логах `ngueu_bot` обнаружена ошибка `TelegramConflictError: Conflict: terminated by other getUpdates request`.
**Причина:** Тот же BOT_TOKEN запущен одновременно в двух местах (например, на сервере и локально).
**Решение:**
- [ ] Выключить все локальные процессы бота.
- [ ] Если ошибка сохраняется — сбросить токен в `@BotFather`.

### 2. Безопасность Базы Данных
**Проблема:** В логах `ngueu_db` видны сотни попыток подбора пароля: `FATAL: password authentication failed for user "postgres"`.
**Причина:** Порт `5432` проброшен наружу в `docker-compose.yml`.
**Решение:**
- [ ] Удалить секцию `ports: - "5432:5432"` из `docker-compose.yml`. БД должна быть доступна только внутри сети Docker.

## 📈 Рекомендации по улучшению

### 🧱 Инфраструктура (Docker)
*   **Ротация логов:** Добавить во все сервисы ограничение размера лог-файлов, чтобы они не заняли всё место на диске.
*   **Удаление obsolete-аттрибутов:** Убрать `version: '3.8'` из `docker-compose.yml`.

### 📝 Логирование в коде
*   **Структурированные логи:** Перейти на JSON-формат вывода логов (библиотеки `structlog` или `loguru`). Это позволит в будущем использовать Grafana Loki.
*   **Exception Tracebacks:** Убедиться, что все ошибки логируются через `logger.exception`, чтобы видеть полный путь ошибки, а не только текст.

### 🛡 Безопасность сервера
*   **Fail2Ban:** Установить на Ubuntu сервис `fail2ban` для автоматической блокировки IP-адресов сканеров.
*   **Sentry:** Интегрировать Sentry для моментальных уведомлений об ошибках в Python коде.
